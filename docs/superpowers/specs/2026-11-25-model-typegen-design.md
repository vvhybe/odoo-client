# 0.3.0: Model Type Generator, GitHub Packages, First Trusted Release

Short design (small change). Approved approach: **A** — a function plus a thin command, generating read types.

## Intent

0.3.0 is the first release published through npm trusted publishing (no token). It carries one roadmap item, "Model type generator from `fields_get` output", and the package also goes to GitHub Packages. Today users write their model interfaces by hand for `searchRead<TypedOdooRecord<T>>`. The generator writes them from the server's own field definitions.

**Deadline:** the npm trusted publisher was created on 2026-11-25 and must publish before **2026-11-27 11:48 UTC**, or it expires.

## Goals

- `generateModelTypes(model, fieldsGet)` returns TypeScript source: one exported interface for one model, typed the way `search_read` returns values.
- A command, `npx @vvhybe/odoo-client typegen <model...> [--out <file>]`, logs in, calls `fields_get` for each model and writes the interfaces to a file, or to stdout without `--out`.
- Deterministic output, so generated files diff cleanly: no timestamp, no server URL or database name, fields sorted by name.
- Published to npm (trusted publishing, with provenance) and to GitHub Packages.

## Non-Goals

- Types for `create` / `write` values (approach C), for a later release.
- Generating every model of a database, watch mode, or a config file.
- Runtime validation of records.

## Anti-Goals

- New runtime dependencies. The command uses Node built-ins only (`node:util` `parseArgs`, `node:fs/promises`).
- Secrets on the command line or in the output. Credentials come from environment variables only.

## Approaches

- **A. Function and command, read types (chosen).** It covers the common use (typing `searchRead`) and keeps the release small.
- B. Function only: every user would have to write their own connect-and-write script.
- C. A plus create/write types: doubles the rules (required, readonly, x2many commands). Deferred.

## Design

**Files:**
- `src/typegen/generate.ts`: the pure function, exported from the package root.
- `src/typegen/cli.ts`: the command.
- `package.json`: `"bin": { "odoo-client": "./dist/typegen/cli.js" }`, so `npx @vvhybe/odoo-client typegen …` runs it.

**Interface name:** the model name in PascalCase: `pos.restock.request.line` → `PosRestockRequestLine`, `res.partner` → `ResPartner`.

**Type mapping (read values):**

| Odoo type | TypeScript |
| --- | --- |
| `id` field | `number` |
| `char`, `text`, `html` | `string \| false` |
| `integer`, `float`, `monetary` | `number` |
| `boolean` | `boolean` |
| `date`, `datetime` | `string \| false` |
| `selection` | union of its keys (as JSON literals), then `\| false` |
| `many2one` | `[number, string] \| false` |
| `one2many`, `many2many` | `number[]` |
| `binary` | `string \| false` |
| `reference` | `string \| false` |
| `many2one_reference` | `number \| false` |
| `json`, `properties`, `properties_definition`, anything else | `unknown` |

**Doc comment on each field:** the label, plus the relation for relational fields (e.g. `/** Product (product.product) */`). Date and datetime comments say "YYYY-MM-DD" and "YYYY-MM-DD HH:MM:SS, UTC".

**All properties are non-optional.** The README shows `Pick<ResPartner, "name" | "email">` for a `searchRead` limited to some fields.

**`OdooFieldType`** gains `json`, `properties`, `properties_definition` and `many2one_reference`, which Odoo 17+ returns. This widens the type and breaks nothing.

**Command:**
- Environment: `ODOO_URL`, `ODOO_DB`, `ODOO_USERNAME`, and either `ODOO_PASSWORD` or `ODOO_API_KEY`, plus optional `ODOO_VERSION`.
- With an API key the command uses XML-RPC, because the library's API-key login gives no JSON-RPC session.
- `fields_get` is called with the attributes `type`, `string`, `relation` and `selection`.
- Exit codes: 0 on success. 1 on a usage error or a missing variable, with a message listing what is missing. 2 when Odoo fails: the typed error class and its message, never a stack trace.
- `--help` prints the usage.

**Output file:** a header comment `// Generated by @vvhybe/odoo-client typegen — do not edit by hand.`, then the interfaces in the order the models were given.

**GitHub Packages:**
- A `publish-github` job in `publish.yml` runs after `publish-npm`.
- Job-level permissions are `contents: read, packages: write` and nothing else. With no `id-token`, npm does not attempt OIDC there.
- `setup-node` uses registry `https://npm.pkg.github.com` and scope `@vvhybe`, with `NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`.
- `create-release` keeps depending on `publish-npm` only.
- The README gets an "Install from GitHub Packages" note: an `.npmrc` scope line and a classic token with `read:packages`.

## Verification

- Unit tests: the mapping table, with a fixture captured from a real Odoo 18 `fields_get` (`pos.restock.request.line`, plus a `res.partner` subset covering `selection`, `many2many`, `binary` and `json`); naming; deterministic output; command arguments, environment errors and exit codes, with a fake client.
- Live: run the built command against a local Odoo 18 for `res.partner` and `pos.restock.request.line`, then compile the generated file with `tsc --noEmit --strict`.
